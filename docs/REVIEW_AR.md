# تقييم UmbraProxy وخطة تطويره

تاريخ المراجعة: 16 نوفمبر 2026. المرجع الأصلي: الفرع `master` عند الالتزام
`62713ba42b42bc9073f81d2fd3b705c610b78692`، الإصدار المعلن `1.4.1`.

شملت المراجعة جميع ملفات Kotlin وGo، إعدادات Android وGradle، موارد النصوص،
والصلاحيات ومسار الإصدار. تميّز هذه الوثيقة بين نتائج قراءة الكود، والاختبارات
المنفذة، وما يحتاج تجربة فعلية. لم تُجرَ تجربة اتصال نهائي بتيليجرام على هاتف.

## الحكم العام

المشروع أساس مناسب لتطبيق شخصي، لكنه يحتاج اختبارات تشغيل وأمان وتسليم قبل
اعتباره إصدارًا إنتاجيًا موثوقًا. تقديري الهندسي للنسخة الأصلية **5/10**؛ هذا
تقدير لجاهزية المشروع، وليس نتيجة قياس أداء أو تدقيق أمني مستقل.

| المحور | التقدير الأصلي | السبب |
| --- | --- | --- |
| تجربة الاستخدام | 7/10 | Compose، مظاهر متعددة، سجلات، اختصار الإعدادات السريعة |
| تنظيم الكود | 5/10 | فصل الواجهة عن النواة موجود، لكن النواة نحو 3 آلاف سطر وحالتها عامة |
| الأمان | 4/10 | التحقق من TLS معطّل، ومفتاح افتراضي معروف، ونسخ احتياطي غير مقيد |
| الاعتمادية | 5/10 | مهلات ومسارات بديلة جيدة، لكن دورة الإيقاف وإعادة التشغيل بها أخطاء |
| الاختبارات | 2/10 | لا توجد اختبارات Go أو Kotlin في النسخة الأصلية |
| البناء والتسليم | 4/10 | مسار يدوي ينشر ملفات غير موقعة، ولا README أو بوابة فحص للتغييرات |

لا أعطي النسخة المعدلة درجة إنتاجية أعلى لمجرد نجاح البناء؛ يلزم اختبارها على
أجهزة وشبكات حقيقية وقياس استقرارها واستهلاكها.

## كيف يعمل المشروع

```text
واجهة Compose / زر الإعدادات السريعة / مستقبل الإقلاع
                ↓
ProxyController → إعدادات DataStore → ProxyService
                ↓                         ↓
        إشعار وحالة وإحصاءات       NativeProxy / JNA
                                          ↓
                              Go: مستمع محلي 127.0.0.1
                                          ↓
                 WebSocket مباشر → توجيه CF اختياري → TCP بديل
```

تيليجرام يتصل بالمستمع المحلي باستخدام مفتاح MTProto. النواة تتحقق من ترويسة
الاتصال وتعيد تشفير النقل وتختار المسار. FakeTLS طبقة تمويه اختيارية. التطبيق
ليس VPN عامًا، ولا تُثبت عبارة اتصال الخدمة إمكانية الوصول إلى خوادم تيليجرام.

نقاط القوة: استخدام مكتبات Go القياسية للتشفير، مستمع محلي افتراضي، عدادات ذرية،
مهلات اتصال، منع محاولات CF الزائدة، تراجع بعد HTTP 429، وحدود لبعض أحجام
الرسائل والسجلات. هذه أساسات مفيدة للبناء عليها.

## نتائج المراجعة والإصلاحات المنفذة

| الأولوية | المشكلة في النسخة الأصلية | التعديل |
| --- | --- | --- |
| عالية | `wsConnectOnce` يستخدم `InsecureSkipVerify=true` | أُعيد التحقق من الشهادة والاسم، مع حد أدنى TLS 1.2 |
| عالية | قبول HTTP 101 دون التحقق من تحدي WebSocket | فحص Accept وUpgrade وConnection والبروتوكول والامتدادات، وتقييد حجم الترويسات |
| عالية | `Close` يخرج إذا سبق أن وُسم WebSocket بالمغلق بعد خطأ | إغلاق المقبس فعليًا مرة واحدة، وإلغاء الكاتب المحجوب مباشرة |
| عالية | `StopProxy` يعود قبل انتهاء المستمع والعملاء | انتظار انتهاء الخادم، وإغلاق العملاء عند الإلغاء، ثم تصفير الحالة |
| عالية | إعادة التشغيل قد تتصادم مع المنفذ السابق أو عملاء سابقين | تسلسل البدء والإيقاف، وإزالة سباق Add/Wait، واختبار 25 دورة متتابعة |
| عالية | مفتاح غير صالح يُتجاهل وتُستخدم القيمة السابقة أو الافتراضية | رفض البدء بمفتاح غير صالح أو صفري؛ توليد 16 بايت عشوائية وحفظها ذريًا |
| عالية | حدث إعادة إنشاء الخدمة بـIntent فارغ يفقد إعداداتها | استعادة الإعدادات المحفوظة بدل البدء بقيم افتراضية |
| متوسطة | مراقبة الشبكة بلا إذن `ACCESS_NETWORK_STATE` | إضافة الإذن ومراقبة الشبكة الافتراضية بدل كل شبكة متاحة |
| متوسطة | تعديل مهمة إعادة الاتصال من خيط callbacks مختلف | تمرير أحداث الشبكة عبر نطاق الخدمة في الخيط الرئيسي |
| متوسطة | احتمال بقاء النواة بعد تدمير الخدمة | إيقاف النواة وتصفير الحالة عند التدمير، وتسلسل عمليات JNA للبدء والإيقاف |
| متوسطة | النطاق المخصص `.com` يتحول أثناء فك ترميز قائمة النطاقات | فصل فك ترميز القائمة عن التحقق من النطاقات المخصصة |
| متوسطة | تحليل DC يتجاهل المدخلات الخاطئة ولا يدعم IPv6 بصورة صحيحة | تحقق صريح، ورفض التكرار، ودعم فصل رقم DC عن عنوان IPv6 |
| متوسطة | طول MTProto معلن ضخم قد يبقي المخزن ينمو | تعطيل تقسيم الحزم فوق 16 MiB وتمرير البيانات دون الاستمرار في تجميعها |
| متوسطة | فترة قراءة FakeTLS تفقد المهلة بعد قراءة البايت الأول | إبقاء مهلة المصافحة حتى اكتمالها |
| متوسطة | مقارنة HMAC بايتًا بايتًا | استخدام `hmac.Equal` |
| متوسطة | إعادة إنشاء loggers مع احتمال بقاء مهام خلفية قديمة | تثبيت كائنات التسجيل واستخدام متغير ذري لتفعيل سجلات التصحيح |
| متوسطة | إعدادات المفتاح تدخل النسخ الاحتياطي افتراضيًا | تعطيل النسخ وربط قواعد استبعاد النسخ السحابي ونقل الجهاز |
| منخفضة | إذن استعراض جميع التطبيقات دون استخدام | إزالة `QUERY_ALL_PACKAGES` |
| متوسطة | تهيئة JNA خارج معالجة الخطأ في قراءة النصوص | معالجة فشل التحميل والتحرير في مكان واحد، مع تحديد UTF-8 |
| متوسطة | مسار تخزين نطاقات CF غير موصول عبر JNA | ربطه بمجلد cache الخاص بالتطبيق |
| منخفضة | قيمة التنزيل الأخيرة تتحول إلى صفر عند عدم وجود فاصل | إصلاح استخراج آخر حقل من ملخص الإحصاءات |
| منخفضة | الواجهة تعدّل إعدادات النواة فقط لتكوين رابط المشاركة | إنشاء بادئة المفتاح محليًا دون تحميل JNA أو تغيير الخدمة |
| منخفضة | يمكن تعديل بعض الإعدادات أثناء بدء الاتصال | تعطيلها خلال البدء أيضًا |
| منخفضة | اختيار حجم تجمع الاتصالات لا يستخدمه مسار العملاء | إخفاء الاختيار؛ يبقى إكمال آلية التجمع عملًا مستقبليًا |
| منخفضة | دعم العربية معلن في البناء دون موارد عربية | إضافة ترجمة النصوص وشريط المظهر وحالة الاختصار |
| منخفضة | التشغيل عند الإقلاع له إعداد مخزن دون مفتاح ظاهر | إضافة مفتاحه للواجهة |
| متوسطة | JNA قديم بالنسبة لدعم محاذاة الصفحات الحديثة | تحديثه من 5.14.0 إلى 5.19.1؛ فحص محاذاة الحزمة لا يغني عن اختبار الجهاز |
| متوسطة | Java 17 في CI مقابل طلب daemon بإصدار 21 | توحيد Java على 17 وإزالة روابط تنزيل خاصة بالنظام |
| متوسطة | خطوة NDK المشروطة بالكاش قد لا تضبط متغير المسار | تثبيت نسخة NDK محددة وبناء المكتبات بسكربت موحد يستهدف API 26 |
| متوسطة | نشر APK غير موقع مع وسم لا يطابق إصدار التطبيق | إعداد مسودة مرشح إصدار غير موقع بوسم مشتق من الإصدار |
| متوسطة | لا توجد بوابة فحص للتغييرات | إضافة CI لاختبارات Go وKotlin وLint وبناء APK |

يمكن أن ترفض النواة الآن نطاقات ذات شهادات غير صالحة كانت تعمل سابقًا بسبب
تعطيل التحقق. الحل تصحيح الشهادة أو النطاق؛ لا يُعاد تعطيل التحقق لتجاوز الخطأ.
وإصلاح المفتاح المخزن غير الصالح يستلزم تحديث رابط البروكسي داخل تيليجرام.

## ما لم يُحسم بعد

1. **تجربة الخدمة على أندرويد فعلي:** القتل وإعادة الإنشاء، الإيقاف أثناء البدء،
   الإقلاع، وإدارة البطارية تختلف بين الشركات وإصدارات النظام. فحص المنفذ الحالي
   يعمل مرة واحدة؛ ليس مراقب صحة مستمرًا للمسار الخارجي.
2. **WebSocket:** قارئ الإطارات الحالي يحتاج دعمًا كاملًا للتجزئة والتحقق من RSV
   والإطارات الضابطة. لا تمثل اختبارات المصافحة تدقيقًا كاملًا للبروتوكول.
3. **التجمع:** `WsPool.Get` و`Warmup` لا يُستدعيان في مسار العملاء. لا يصح الادعاء
   بأن تغيير حجم التجمع يحسن الأداء قبل ربطه واختباره وإغلاق عمليات إعادة ملئه.
4. **السجلات:** قناة محدودة قد تُسقط سطورًا دون عداد؛ والمسح قد يتزامن مع دفعة
   منتظرة. يحتاج تشغيل logcat وإيقافه إلى اختبار متكرر لتجنب بقاء عمليات قديمة.
5. **الطاقة:** WakeLock يُجدد دوريًا، وطلب استثناء البطارية يظهر مبكرًا. يجب قياس
   الاستهلاك قبل تقرير ضرورة هذه السياسة أو وصفها بالموفرة للطاقة.
6. **مصادر التوجيه:** قائمة النطاقات تُجلب من مشروع خارجي، مع قائمة احتياطية
   مضمنة. TLS يحمي الاتصال بالمصدر، لكنه لا يضمن موثوقية مشغلي خوادم التوجيه.
7. **البنية:** `MainActivity` كبير، و`saveAll` يكتب إعدادات كثيرة مع كل تحرير.
   تُقرأ إعدادات الاتصال عبر تدفقات منفصلة؛ الأفضل لاحقًا لقطة إعدادات واحدة
   ونموذج حالة وViewModel وإجراءات حفظ محددة.
8. **المفاتيح:** ما زال المفتاح في تخزين التطبيق الخاص ويمكن عرضه ونسخه. منع
   النسخ الاحتياطي لا يحوله إلى تخزين مشفر ولا يحمي هاتفًا مخترقًا.
9. **إعدادات البناء:** بعض قواعد R8 تحفظ حزم Compose وCoroutines وDataStore
   بالكامل وتخفي تحذيرات واسعة. لا يُقاس أثرها على الحجم دون مقارنة إصدار مضغوط.
10. **النشر:** يلزم مفتاح توقيع الإنتاج الأصلي، ورفع رقم الإصدار عند الإصدار،
    ومراجعة targetSdk وفق قناة التوزيع. لا يوجد ملف ترخيص يحدد إعادة استخدام الكود.

## خطة تطوير بمعايير قبول

| المرحلة | العمل | معيار الانتهاء |
| --- | --- | --- |
| الأولى — هذه التعديلات | إصلاحات الأمان ودورة الخدمة واختبارات الرجوع وCI | فحوص البناء والاختبارات تمر، مع مراجعة التغييرات |
| الثانية — اعتماد التشغيل | أجهزة ARM64 وARMv7؛ Android 8 و13 و15+؛ جهاز صفحات 16 KB | اتصال تيليجرام فعلي، تبديل شبكات، قتل الخدمة، وإعادة تشغيل الهاتف دون تسريب |
| الثالثة — تنظيم واختبار | تقسيم نواة Go إلى إعدادات/نقل/تشفير/خادم؛ ViewModel وحالة خدمة موحدة | اختبارات لوحدات النقل، وإعدادات ذرية، وحالات بدء/تشغيل/إعادة اتصال/خطأ/توقف واضحة |
| الرابعة — الأداء | إكمال التجمع، اختبار ضغط، قياس بطارية وذاكرة | مقارنة قبل/بعد لزمن بدء الاتصال p50 وp95، والذاكرة، وعدد المقابس واستهلاك الطاقة |
| الخامسة — الإصدار | ضبط R8، التوقيع، وثائق الخصوصية والتوزيع والتبعيات | APK موقع بالمفتاح الصحيح، تثبيت وترقية ناجحان، ومسار رجوع موثق |

لا توجد أرقام مثبتة لتحسن السرعة أو البطارية؛ يلزم قياسها. أقترح البدء بالمرحلة
الثانية قبل إضافة بروتوكولات جديدة أو إعادة تصميم شاملة للواجهة.

## التحقق

الأوامر والتقرير النهائي للنتائج موجودة في قسم «نتائج التنفيذ» أدناه. اختبارات
الرجوع تستخدم اتصالات loopback، ولا تعتمد على توفر تيليجرام أو خوادم CF.

قائمة التجربة اليدوية قبل اعتماد الإصدار:

- تشغيل/إيقاف سريع 25 مرة، وإيقاف أثناء البدء وأثناء تغيير الشبكة.
- Wi‑Fi ←→ بيانات الهاتف، ووضع الطيران ثم العودة، ووجود VPN آخر.
- قتل عملية التطبيق وإعادة إنشاء الخدمة؛ ثم السحب من التطبيقات الحديثة.
- إعادة تشغيل الجهاز مع خيار التشغيل التلقائي مفعّلًا ومعطّلًا.
- نطاق مخصص صالح وآخر خاطئ، وFakeTLS مفعّل ومعطّل، وDC يدوي IPv4 وIPv6.
- فتح تيليجرام والتحقق من إرسال الرسائل والوسائط؛ لا يكفي أن المنفذ مفتوح.
- العربية وRTL، وأحجام خطوط كبيرة، واختصار الإعدادات السريعة، والسجلات.
- تثبيت ARM64 وARMv7، وصفحات 16 KB، والتوقيع والترقية بمفتاح الإصدار الحالي.

## نتائج التنفيذ

- **Go:** نجحت اختبارات الرجوع العشرة، مع `go test -race -cover ./...`
  و`go vet ./...`. تغطية العبارات **25.3%**؛ ليست تغطية كاملة للنواة.
- **إثبات العطل الأصلي:** فشل اختبار إغلاق WebSocket بعد خطأ القراءة/الكتابة
  على الالتزام الأصلي، ونجح مع الإصلاح. أُجري الاختبار في نسخة منفصلة.
- **اختبار عشوائي:** نجح `FuzzUpgradeParser` لمدة 10 ثوانٍ، وشغّل
  **193,863** حالة دون فشل. يخص محلل المصافحة فقط.
- **واجهة C:** بُنيت مكتبة Linux مشتركة وجُربت عبر `ctypes`، مع 25 دورة
  تشغيل/إيقاف وقراءة/تحرير الإحصاءات ورفض مفتاح غير صالح.
- **Kotlin:** نجحت الاختبارات الخمسة الخاصة بتوليد المفتاح، ورفض المدخلات،
  وتكوين بادئات روابط MTProto وFakeTLS.
- **Android Lint:** اكتمل دون أخطاء مانعة. بقيت **47 ملاحظة تحذيرية**، منها
  إصدارات أحدث للتبعيات وtargetSdk، وموارد غير مستعملة واقتراحات أسلوبية.
- **البناء الأصلي:** بُنيت مكتبتا ARM64 وARMv7 باستخدام Go 1.26.11
  وNDK 27.2.12479018، مع API 26.
- **APK:** نجح بناء Debug وRelease. إصدار Release غير موقع؛ يحتاج مفتاح
  الإنتاج قبل التوزيع. نسخة Debug موقعة بمفتاح اختبار.
- **محاذاة الحزمة:** اجتاز APK فحص `zipalign -c -P 16 4`؛ كما اجتازت
  جميع المكتبات المشتركة الثماني المضمنة في الحزمة العامة فحص محاذاة ELF
  بمقدار 16 KB على الأقل، بما فيها JNA وDataStore ومكتبة الرسوميات.
- **سلامة الحزمة:** طابقت بصمات مكتبتي Go داخل APK الملفات المبنية من المصدر
  الحالي. فُحص توقيع APK التجريبي باستخدام `apksigner`.
- **الموارد والإعداد:** ملفات XML وYAML صالحة، ومفاتيح النصوص العربية
  والإنجليزية متطابقة، ونجح فحص صياغة سكربت البناء و`git diff --check`.

لم تُنفذ اختبارات أجهزة Android أو اتصال تيليجرام الفعلي أو قياسات البطارية
والضغط. كذلك لم تتحول نتائج الفحص المحلي إلى إثبات لتشغيل GitHub Actions
عن بُعد؛ حالة تلك الفحوص تُراجع في طلب الدمج عند تشغيلها.
